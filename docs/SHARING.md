# 共有リンク（Cloudflare Worker + D1）

アカウントなしで、リンクを知っている人どうしが、同じ旅行を見て、記録できます。サーバーは、アプリと同じCloudflareのWorker（`worker/index.js`）で、データはD1（SQLite）に置きます。

## 仕組み
- 共有を始めると、アプリが **32文字のランダムなトークン**をつくります。共有リンクは `https://<URL>/#t=<トークン>`。`#` より後ろは、ブラウザからサーバーへ送られません。
- サーバーには、トークンの **SHA-256 ハッシュ**だけが、旅行のIDとして保存されます。データベースが漏れても、リンクは分かりません。
- 読み書きは、`Authorization: Bearer <トークン>` で、その旅行1件だけに限られます。ほかの旅行は、見えも、書けもしません。
- 同期は、端末の旅行と、最後にサーバーへ送れた状態との**差分**だけを送ります（`sync.js` の `Sync.diff`）。送れなければ、つながったときに自動で再送します。
- ほかの人の変更は、約8秒ごと（と、アプリに戻ったとき）に確認して、反映します。入力フォームを開いている間は、データを差し替えません。
- 同じ行を同時に直したときは、あとから送った方が勝ちます。

## 公開（初回）
1. `main` に反映すると、Cloudflare が `npm run build` → `npx wrangler deploy` を実行します。
2. D1データベース `tabiwari` は、初回のデプロイで、Wrangler が自動でつくります（`wrangler.jsonc` に `database_id` は書いていません）。テーブルも、最初のアクセスで自動作成されます。
3. もしデプロイが「database_id が必要」というエラーで止まったら：Cloudflare の **Storage & Databases → D1 → Create database**（名前 `tabiwari`）で作成し、表示された Database ID を `wrangler.jsonc` の `d1_databases` に `"database_id": "..."` として足して、push します。

## 上限・保護
- 旅行1件あたり：メンバー12人、支出2,000件、支払い済みの印500件。1回の送信は256KBまで。
- 1つの接続元あたり：旅行の新規作成は1日20回、書き込みは10分あたり300回まで（超えると、しばらく待つよう表示）。
- 不正な内容（想定外の列、範囲外の数字、存在しないカテゴリなど）を1つでも含む送信は、**全体を拒否**し、何も反映しません。
- 400日、誰も更新しなかった旅行は、毎日の定期処理で削除します（`worker/index.js` の `RETENTION_DAYS`）。

## 注意（プライバシー）
- リンクを知っている人は、誰でも、見て、記録できます。LINEなどで、旅行に行く人にだけ送ってください。
- 旅行の名前、メンバーの名前、支出の内容と金額が、サーバー（Cloudflare D1）に保存されます。メールアドレスなどは、集めません。
- `privacy.html` と `terms.html` は、この仕組みに合わせて書き直してあります。運営者名などの `【要記入】` を埋めて、`config.js` の `legalReady` を `true` にしてください（`node test/launch-check.js`）。

## iPhone のホーム画面アプリについて
iPhone では、ホーム画面に追加したアプリと、Safari は、保存領域が別です。LINEのリンクを開くと Safari で開くので、ホーム画面のアプリには入りません。アプリの中で参加するには、リンクをコピーして、アプリのホームの **「共有リンクで参加する」** に貼り付けてもらいます。

## テスト
```
npm test                   # 計算ロジック・同期の差分・リンクの解析
npm run test:share         # ビルド → サーバーのAPI（権限・不正入力・上限）→ ブラウザで複数人の共有
```
`test:share` は、`wrangler dev --local`（ローカルのWorker + D1。Cloudflareへのログイン不要）を自動で起動し、playwright が必要です。
