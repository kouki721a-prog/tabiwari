# LINEログインとバックアップ

旅行のバックアップ（と、別の端末で戻す機能）のための、LINEログインの設定です。**設定するまでは、アプリにログインの表示は出ません**（共有リンクは、ログインなしで使えます）。

## 1. LINE Developers でチャネルをつくる
1. https://developers.line.biz/console/ を開き、LINEアカウントでログインします。
2. **プロバイダー** を新規作成します（名前は自由。例：`tabiwari`）。
3. そのプロバイダーの中で **新規チャネル作成 →「LINEログイン」** を選びます。
   - 地域：日本
   - チャネル名：たびわり
   - アプリタイプ：**ウェブアプリ**
   - 規約に同意して、作成。
4. 作成したチャネルの **「LINEログイン」タブ → コールバックURL** に、次をそのまま登録します（1文字でも違うとエラーになります）。
   ```
   https://tabiwari.tabiwari-app.workers.dev/api/auth/line/callback
   ```
   独自ドメインにしたときは、そのドメインで、もう1つ追加します。
5. **「チャネル基本設定」** にある、**チャネルID** と **チャネルシークレット** を、控えます。

## 2. Cloudflare に登録する（3つ。すべて「シークレット」）
Cloudflare → Workers & Pages → `tabiwari` → **設定 → 変数とシークレット → 追加**。種類は、3つとも **シークレット** にします（ビルドのたびに、消されたり、上書きされたりしません）。

| 名前 | 値 |
|---|---|
| `LINE_CHANNEL_ID` | チャネルID |
| `LINE_CHANNEL_SECRET` | チャネルシークレット |
| `LINE_OA_ACCESS_TOKEN` | 公式アカウント（Messaging API）のチャネルアクセストークン。精算の確定を、友だちにLINEで送るのに使う。LINEログインのチャネルと、同じプロバイダーに置くこと |
| `AUTH_SECRET` | 自分でつくった、**32文字以上のランダムな文字列**（パスワード管理アプリの「ランダム生成」が便利） |

保存して **デプロイ** します。`AUTH_SECRET` は、バックアップの暗号化の元になります。**あとで変えると、保存済みのバックアップが読めなくなる**ので、控えておいて、変えないでください。

## 3. 確認する
アプリのホームに「LINEでログインすると、旅行をバックアップして…」のカードが出れば、設定できています。ログインして、旅行を作り、別の端末（または別のブラウザ）で、同じLINEでログインして「バックアップから戻す」を試します。

## 4. 友だちにも使ってもらうとき
チャネルは、最初は **開発中**です。開発中は、あなた（と、チャネルに追加したテスター）しかログインできません。友だちに使ってもらうには：
1. 先に、`terms.html` と `privacy.html` の `【要記入】` を埋めて（専門家の確認もおすすめ）、`config.js` の `legalReady` を `true` にして公開します。
2. LINE Developers のチャネルで、**プライバシーポリシーURL**（`https://…/privacy.html`）と **利用規約URL** を登録します。
3. チャネルの **ステータスを「公開済み」** にします。
4. LINEの「ログインボタンのデザインガイドライン」に沿って、ボタンを、公式の素材に差し替えるのが望ましいです（いまは、緑色のボタンで代用しています）。

## つまずいたとき
- **「redirect_uri が一致しません」**：コールバックURLを、上の文字列と、1文字ずつ比べてください（`https`、末尾に `/` がない、など）。
- **ログインのカードが出ない**：3つのシークレットがそろっているか（`AUTH_SECRET` は32文字以上）。保存後に、デプロイしたか。
- **ログインに成功するのに、アプリが「待っています」のまま**：LINEの確認画面を閉じて、アプリに戻り、数秒待ちます。10分たつと、やり直しになります。

## 仕組み（メモ）
- ログインは、LINEの標準的な認証（OpenID Connect）を、Worker（`worker/account.js`）が、直接つなぎます。取得するのは `profile`、`openid` だけで、メールアドレスは取りません。プロフィール画像も、保存しません。
- アプリは、ログインを開始すると、サーバーから「待ち受け」の番号と、本人だけが持つ合言葉をもらい、LINEの画面へ進みます。LINEの画面が、ホーム画面のアプリとは別のブラウザで開いても、アプリは、合言葉で、完了を受け取れます（iPhoneで起きる状況への対策）。
- ログイン状態は、`HttpOnly` の Cookie（90日）。ほかのサイトからの書き込みは、`Origin` の確認で、拒否します。
- バックアップは、旅行ごとに、AES-GCM で暗号化して D1 に保存します（鍵は `AUTH_SECRET` から作ります）。共有している旅行は、合言葉と自分の枠だけを控え、戻すときに、サーバーから最新を取ります。戻すときは、旅行のデータを、アプリが書く項目だけに作り直して取り込みます。
- 1アカウント：旅行100件まで。400日ログインがないアカウントは、バックアップごと、自動で削除します。

## テスト
```
npm run test:account   # 疑似LINEで、ログイン、バックアップ、別の端末での復元、アカウント削除（ローカルWorker + D1）
```
