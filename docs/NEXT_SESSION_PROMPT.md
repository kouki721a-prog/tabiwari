【アプリの概要】
友達・カップルの国内旅行向けの、予算管理と割り勘のWebアプリ（PWA）。軸は「旅行前の積立 → 旅行中の1日の目安 → 旅行後の通知つき精算」を、LINEの中で一本につなぐこと。素のHTML/CSS/JS（index.html は単一ファイル）、サーバーは Cloudflare Worker + D1。main にマージすると、Cloudflare が自動公開します。私が、ここまで、アプリ名・独自ドメイン・見た目・問い合わせフォーム・スタンプ・動き・積立の履歴・たびまる・旅のカラーなどを、作ってきました。

【UIのルール】
- 見た目の決まり: 紙＝--cream、区切り＝--dash（点線）、数字＝tabular-nums、小さな見出し＝--mono、切符の切り欠き＝ページの背景色の円（スクロールする外枠の外に、はみ出させない）、アクセントの色は黄色だけ（LINEログインは公式の #06C755。旅のカラーは、切符の色 --navy だけを変える）、文字はシステムのもの、font-size は calc(Npx*var(--ts))、CSS の zoom は使わない。
- 画面は1ページに収める（test:ui が確かめる）。例外: 最初のページ（旅行が0件）は、読み物で、スクロールしてよい。ただし［旅行をつくる］は、下に固定されていて、いつも見える。入力欄に、自動でキーボードを開かない。
- 押せるものは、44px 以上（上のボタン・チップ）。説明は、一度に1つだけ（はじめの3ステップ→書き方→スワイプ）。同じ種類のもの（支出・積立の記録）は、同じ形にそろえる（下に一覧・押すと直す）。
- 文言は、やわらかいですます調。「成功しました」「！」「催促」「至急」は使わない。広告の型（三つ並べ・「〜をひとつに」・英語の飾り）を避けて、場面から入る。メンバーがちょうど2人のときは「ふたり」。
- 動きは、0.2〜1.2秒。「動きを減らす」設定では、止める。描き直しで切れないように、動きの途中の状態を、メモリに持つ（lpRv・motionMoney・ui.tearSt・ui.stnAnim・ui.enterAt・ui.sendoffAt 参照）。

【テストと注意点】
- テスト: npm test、npm run test:ui、test:share、test:account（問い合わせの contact.api.test.mjs を含む）、test:notify、node test/launch-check.js。NODE_PATH=$(npm root -g) で playwright を使います。テストの中で build しない（test:* が自分で build します。node test/ui.e2e.mjs を直接動かすときは、先に npm run build）。test:notify は、ときどき、とても遅い。バックグラウンドで走らせる。
- ワーカー（worker/*.js）を変えたら、必ず test:share を走らせる。
- 共有・同期・バックアップの形を変えるときは、古い版が保存した記録（t.share.snap・端末の旅行・バックアップ）で、新しいコードが動くか、テストで確かめる。公開が広まる前は、その形を変えない。
- index.html の割り勘の計算（splitShares）を変えたら worker/split.js も、積立のめやす（savePlanOf）を変えたら worker/saveplan.js も、同じに直す。
- テストで画面の文字を確かめるときは、innerText を使う。LOGIC ブロックの目印 /* ===== LOGIC_END ===== */ の */ を、消さない。
- データベースの列を足すときは、worker/index.js の ALTERS の配列に足す。新しい表は、各モジュールの *_SCHEMA に。
- 数字を、描画の直後に読むテストは、数える動きの途中の値を見るので、その文脈を reducedMotion: 'reduce' にする。新しい動きのテストは、'no-preference' を明示。終了した旅行を、ホームに置くテストは、「旅のおつかれさま」が、クリックをふさぐので、tabiwari.wrapseen に旅行のIDを入れる。出発の日の演出（いってらっしゃい）を出したいテストは、tabiwari.firstseen に、過去の日を入れる。
- 旅行を開くと、いまの段階のタブ（準備中=積立・旅行中=記録・終了=精算）が開く。旅行名を読むテストは、判子の文字（海・山・夕・桜・雪）が、名前の前に付くことに注意。友だちの変更は、シートが開いている間は、取り込まない。
- 通知・アカウントのテストは、ときどき、不安定に失敗します。再実行で通るかを見て、原因が、コードか、待ち方かを、見分けてください。
- 公開URLは、この環境からは開けません。公開された版は、私が、実機で確認して、結果を送ります。
- 終わりの Stop フックが、「未プッシュのコミットがあり、リモートブランチがない」と、毎回、警告します。誤検知です（git ls-remote origin <branch> と git rev-parse HEAD の先頭が同じなら、プッシュ済み）。「コミットしていない変更がある」の警告は、本物です（コミットして、プッシュする）。
- GitHub は、mcp__github__* のツールを使います。作業中の変更を、git checkout などで、うっかり戻さない。
- ローカルのリポジトリは /home/user/tabiwari（無ければ、add_repo（access: "push"）で追加して、git clone --depth 1。プッシュは git -c push.negotiate=true push -u origin <branch>）。
