# 通知（Web Push）

LINEでログインした人が、端末ごとに、アプリの「アカウント → この端末への通知 → 受け取る」で、オンにします。**サーバー側の追加設定は、要りません**（通知の鍵は、サーバーが初回に自動でつくり、D1に保管します。秘密の半分は、`AUTH_SECRET` から作った鍵で暗号化して保存します）。

## 送る通知（日本時間。同じ人・旅行・種類・日に、1回だけ）
| 種類 | いつ | 文面 |
|---|---|---|
| 前日 | 旅行の前日の18時以降 | 「明日から 「〇〇」」 |
| 記録のし忘れ | 旅行中の20時以降に、その日の記録が、まだ1件もないとき | 「今日の支出を記録しましょう」 |
| 精算 | 旅行の翌朝10時以降に、支出が1件以上あったとき | 「精算を済ませましょう」 |

## 仕組み
- 毎時（`wrangler.jsonc` の `triggers.crons`）、Worker の `scheduled` が `worker/reminders.js` を動かします。
- 対象は、通知をオンにした人の、**暗号化バックアップ**に入っている旅行です。サーバーは、判定のために、その場で暗号を解いて、旅行の名前と日程を読みます（共有している旅行の「記録があるか」は、D1の共有データを、合言葉のハッシュで引きます）。バックアップは、変更の約4秒後に、自動で更新されます。
- 送る前に、`(人, 旅行, 種類, 日)` を D1 に記録して、二重に送らないようにします。配信サービスが一時的に失敗したときは、記録を外して、次の1時間で、もう一度試します。
- 配信は、Web Push の標準（VAPID + aes128gcm 暗号化）。通知の中身は、端末だけが解読できます。配信サービス（Apple、Google、Mozilla、Microsoft）は、中身を読めません。
- 「無効」と返された宛先は、自動で削除します。宛先は、本物の配信サービスのURL（`fcm.googleapis.com`、`web.push.apple.com`、`updates.push.services.mozilla.com`、`*.notify.windows.com`）だけを受け付けます（ほかのURLに、Workerが送ることはありません）。
- 無料プランでは、1回の実行で、外へ送れる数に上限があります。1回の実行は、最大40件（1台1件ずつなら40台分）まで。収まらなかった分は、次の1時間に回ります。

## 使える環境
- **iPhone**：ホーム画面に追加したアプリで、iOS 16.4 以降。Safariで開いているだけでは、通知は使えません（アプリが、その旨を表示します）。
- Android の Chrome、パソコンの Chrome・Edge・Firefox：そのまま使えます。
- 通知を、ブラウザや端末の設定で、拒否している場合は、先に、設定で許可してもらいます。
- 1アカウントで、10台まで。

## すぐ確かめる（テスト通知）
通知を「受け取る」にしたあと、同じ画面の「送る」を押すと、その場で、テスト通知が1件、**自分の端末だけ**に届きます（本物の配信サービスを通ります。10分に10回まで）。旅行の日付を待たずに、実機で確認できます。

## 止めるとき
- アプリで「止める」を押す、ログアウトする、アカウントを削除する、のどれかで、その端末の宛先を、すぐに削除します。

## つまずいたとき
- **「受け取る」が出ない**：LINEログインが未設定、または、iPhoneでホーム画面に追加していない。
- **通知が来ない**：端末の設定で、通知が許可されているか。旅行が、バックアップされているか（アカウント画面の「バックアップ ○件」）。前日の通知は、旅行の前日の18時以降に、1回だけ届きます。

## テスト
```
npm run test:notify   # 暗号化と署名、毎時の判定、購読、配信と解読、失敗時の再送、解除（疑似の配信サービス）
```
暗号化は、広く使われている参照の実装（`http_ece`）でも、解読できることを、開発時に確かめています。
